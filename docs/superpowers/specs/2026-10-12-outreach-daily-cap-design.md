# Общий суточный лимит Outreach

## Цель

Гарантировать, что Outreach Desk отправляет не более 100 реальных outreach-писем за календарные сутки по часовому поясу приложения. В лимит вместе входят первые письма и follow-up всех запусков и всех почтовых ящиков.

## Поведение

- Значение общего лимита хранится в runtime-настройках как `outreachDailyLimit`; значение по умолчанию — `100`.
- Допустимый диапазон настройки: от `1` до `10000`.
- Учитываются только успешно отправленные исходящие сообщения `type = 'outreach'` и зарезервированные worker элементы очереди `status = 'running'`.
- Тестовые письма и прогрев не входят в общий outreach-лимит.
- Граница суток вычисляется в `runtime.timeZone`, по умолчанию `Europe/Moscow`.
- Если лимит исчерпан, элементы остаются в очереди и будут рассмотрены в следующие сутки.
- Follow-up (шаг с позицией больше 1) выбираются раньше первых писем. Новые письма занимают только оставшийся суточный объём.
- Действующие более низкие лимиты mailbox и campaign также должны соблюдаться.
- Несколько worker не должны совместно превысить лимит: выбор элемента и резервирование квоты сериализуются транзакционной advisory-блокировкой; текущие `running` учитываются как занятые места.

## Управление и безопасность

- Настройка доступна в интерфейсе и возвращается API `/api/settings` и `/api/health`.
- Изменение режима доставки через MCP обязано сохранять текущий суточный лимит.
- Подтверждение запуска через MCP остаётся обязательным.
- Деплой не запускает worker автоматически.

## Проверка

- Нормализация лимита и расчёт доступности квоты покрыты unit-тестами.
- Статические интеграционные проверки подтверждают подключение настройки к API, UI, MCP и worker SQL.
- Полный `npm run check` должен завершаться без ошибок.
